本周经验卡：一串被连带删掉的键

2026-11-20 1013 字 · 3 分钟 经验卡 · 大富翁 · minimaxh3

本周十一张卡：展开「删大段字面量连带删掉相邻键」「礼物是 protobuf」「端口落在系统保留区」三张，其余八张按类归纳。

三张展开

删大段字面量，连带删掉相邻的键

现象：把默认配置里一大段数组整块替换掉，页面初始化第一行就报 Cannot read properties of undefined (reading 'map')。构建照样通过。

做法：先用两端锚点圈定范围（起点 cells:[，终点下一个同级键的开头），并显式检查切出来的片段里不含 gifts:；替换之后在 vm 里 eval 到默认配置定义之后，断言 gifts.length 与 cells.length 都非空。

验证：语法检查和构建脚本都只能证明「语法合法」，数据是运行期才变成 undefined 的。这次是靠整页浏览器用例一起变红才找到，定位成本远高于一句断言。同类事故已经是第二次——上一回是精简 helper 时删掉了被多处调用的 make_buvid3()，mock 扫码静默抛 NameError，测试只看到状态停在 scanned。删整段之前先全文搜引用点。

礼物是 protobuf，字段号比字段名可信

现象：礼物提示未知指令；入局拿到的是粉丝牌名；多个送礼人被合并成同一个人。

做法：礼物事件的顶层前三个字段才是发送者的 uid、昵称、头像。里面那个「勋章对象」的第一个字段是勋章自己的目标 ID，当成 uid 用就会把多个送礼人并成一个；礼物 ID、名称、数量在第十个字段的前三个子字段里，单价、总价、币种在第五、七、八个字段，事件 id、时间戳、随机数在第九、十、十二个字段。解析器对 base64 与 wire 长度做严格校验，事件 ID 优先用 tid。

验证：固定一份样本，发送者、勋章、礼物、数量逐字段比对。两条反例记住了：别拿「相近时间 + 相同昵称」去重，真礼物会被吞；别把整条 pb 打进日志，里面带着身份。

端口没被占用，却报 socket 权限错

现象：服务起不来，报 WinError 10013，可那个端口上没有任何监听进程。

做法：查系统的 TCP 排除区间（netsh interface ipv4 show excludedportrange protocol=tcp），发现有一段连续端口被系统保留，三个常用端口正好落在里面。只读确认候选端口既没监听、也不在排除区之后，把共享的 MCP 地址与受管理的服务一起换到保留区外。

验证：新端口能起、能出图；旧端口重启多少次都还是同一个错。反复重启同端口、杀别人的 Python、停 HNS/WinNAT 都没用——提权也解除不了系统保留区。

其余按类归纳

  • 构建成功 ≠ 能跑：离线单页 HTML 构建通过，但 3D 场景根本没初始化——构建只做语法检查，运行期错误得另开一次冒烟。
  • 中文文件名：用 PowerShell 管道改含中文的脚本，文件名被写成乱码，页面直接找不到文件。改含中文的源码一律用编辑器或 Node。
  • 测试自己空转：预设状态没清干净，用例在「已经是目标状态」的输入上空跑，全绿但什么都没验。
  • 能拖不等于能点：可拖动面板的样式屏蔽了子控件的鼠标事件，拖动与点击要分开验，展开按钮还得放到不被裁切的位置。
  • 多人镜头：一张图里出现两个同款人物、或角色属性串到别人身上，是提示词里的人数与参考图数量对不上。
  • 首尾帧都对，中间熔掉：首尾锚定住了，中段仍会溶变——中间的注意力没被锚住，得靠整轨音频或参考帧去锁。
  • 长任务被切断：MCP 调用有 60 秒上限，长任务要改成轮询任务状态，而不是等一次返回。
  • 端口排除区的排查顺序：先确认进程没在跑，再看它是否落在系统保留段，最后才怀疑权限。
